What this is

A microphone near a keyboard hears every keystroke, and each key sounds a little different. A machine-learning model can turn that sound back into text — including passwords. Published work demonstrates this side channel in some conditions, but results depend on the keyboard, room, microphone, and recording path. This demo does not reproduce real-world attack results.

keydropper is a blue-team tool. It builds a small, honest recognizer only to measure that leak, and then builds and proves an interference model — an active countermeasure that emits decoy keystroke sounds from your own device so the eavesdropper can no longer tell which key you pressed.

The pipeline (all client-side)

  1. Segment the audio into per-keystroke windows (energy onsets).
  2. Featurize each window as a log-mel spectrogram, aligned to its transient peak.
  3. Recognize the key with a compact, efficient classifier.
  4. Interfere: overlay spectrally-matched decoy keystrokes to mask the real ones.
  5. Evaluate: recovery accuracy with vs. without the defense.

Does the defense survive an attacker who knows about it?

The lab also trains an adaptive attacker that collects its training data with the masking already switched on, so it learns the masked sound rather than the clean one. Its result is shown alongside the clean-trained recognizer. Scores come from a simplified synthetic keyboard model and are not a security guarantee for physical devices.

Two things that make recognition work

The keyboard's per-key sound is a fixed identity (same in every recording), and features are aligned to the keystroke's transient — otherwise a model trained on one recording can't read another. The defense is measured against a fair recognizer trained on clean audio.

The app has no analytics or upload endpoint. Audio processing happens in this tab. The microphone mode works over HTTPS (this page on GitHub Pages) or on localhost; the synthetic lab works anywhere, even opened directly from disk.
